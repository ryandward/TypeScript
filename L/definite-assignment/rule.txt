definite-assignment
kind: soundness

Claim. If the lab accepts a program, every class property it reads was assigned by code the checker followed.

Counterexample in plain TypeScript. A property declared with !, as in `name!: string`, turns off the strict
property initialization check for it: the checker takes the assertion's word that something assigns the
property, and nothing has to.

Obligation 1, definite assignment assertion: TS2897
  Statement. A property counts as assigned only where the checker sees the assignment: where it's declared,
  or on every path through the constructor.
  Mechanism. checkPropertyDeclaration reports TS2897 for every property declaration written with !.
  Why it suffices. Without !, strictPropertyInitialization already holds every property to that rule. A let or
  var written with ! has no initializer, so single assignment rejects it first, with TS2892 in let-or-var.
  Witnesses:
    rule-definite.ts                   a property asserted to be assigned that nothing assigns
  Controls:
    constructor-assigned.ts            the constructor assigns it, and the checker follows the constructor
    initialized-property.ts            assigned where it's declared
  Rejected sound code, because the checker doesn't follow calls:
    assigned-by-a-method.ts            a method the constructor calls does assign it

Boundary. TypeORM assigns entity columns itself, so an entity class declares them with !.
