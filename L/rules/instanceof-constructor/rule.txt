instanceof-constructor
kind: soundness

Claim. If the lab accepts a program, the right side of every instanceof is a value with a prototype to check
against, or a value with a Symbol.hasInstance method of its own.

Counterexample in plain TypeScript. Without a Symbol.hasInstance method of its own, instanceof falls to
Function.prototype[Symbol.hasInstance], which reads the right side's prototype. An arrow function, a method and
an async function have none, so Node throws a TypeError for each when the left side is an object. The global
Function interface declares that method for every function as (value: any): boolean, with nothing about the
prototype, and resolveInstanceofExpression resolves the call against it. So the release accepts the witness
below, and Node crashes on it.

Obligation 1, right side with a prototype: TS2901
  Statement. A right side may be accepted only if every value of its type has a prototype object, or its type
  carries a Symbol.hasInstance method that isn't Function's. Function's method needs a prototype that its
  declaration doesn't ask for, so it proves nothing. A construct signature is the only thing in a type that
  promises a prototype, and only as far as the declaration that gives it is honest.
  Mechanism. resolveInstanceofExpression no longer takes Function's own Symbol.hasInstance as the right side's
  method: it compares the method it finds with Function's and falls through when they are the same. Past
  TypeScript's own check for a callable right side, it reports TS2901 unless every member of the right side's
  apparent type has a construct signature.
  Why it suffices. Every instanceof is checked by checkInstanceOfExpression, which resolves the expression's
  signature through resolveInstanceofExpression, so no right side reaches the operator without this
  judgment. Every function type finds Function's method, whether or not it has a construct signature, so
  falling through on it leaves the construct signature as the only evidence. The judgment is made per member
  of a union, because a union of constructors whose signatures differ has no single construct signature.
  In Lean. ../../lean/Top.lean types instanceof only with a constructor on the right, and its sound theorem covers
  that rule. instOfCallable, TypeScript accepting any function on the right, is refuted by the witness's
  program, ({}) instanceof (() => 1). The calculus has no unions and no object with a Symbol.hasInstance
  method of its own, so neither the per-member judgment nor that branch has a counterpart there.
  Witnesses:
    chk-instanceof-method.ts           an object-literal method on the right
    chk-instanceof-arrow.ts            an arrow function on the right
  Controls:
    built-in-constructor.ts            Error, declared with a construct signature
    union-of-constructors.ts           Map or Set, whose union has no construct signature of its own
    type-parameter-constructor.ts      a type parameter bounded by a construct signature, given Map
    own-has-instance.ts                an object with a Symbol.hasInstance method of its own
  Rejected sound code, because the function's type has only a call signature:
    generator-function.ts              a generator function, which has a prototype
    plain-function.ts                  a function declaration, which has a prototype
