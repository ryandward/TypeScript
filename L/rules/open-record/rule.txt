open-record
kind: soundness

Claim. If the lab accepts a program, a read through an index signature is typed as what it may find: an entry or
nothing, and unknown where the key may name a member every object inherits.

Counterexample in plain TypeScript. An object holds its entries and its prototype's members under the same keys,
so a Record<string, number> read at constructor, toString or __proto__ finds Object.prototype's member, or an
entry of that name, and the index signature types either as a number. A key of type string may be any of those
names, and a literal key Object declares was typed as the index signature's too, since
getIndexedAccessTypeOrUndefined replaced any string key of a type with only a string index signature by string
itself. Each witness reads an inherited member as a number, and Node throws a TypeError.

Obligation 1, a read that may find an inherited member, used as an entry: TS2339 (TypeScript's code)
  Statement. A read of a dictionary, a type whose index signature applies at a name every object inherits and which
  doesn't declare that name itself, by a key that may be that name, is unknown. A literal key naming no inherited
  member, a number, or a template literal type such as `data-${string}` reads an entry or nothing, the index
  signature's type with undefined. A record without an index signature is judged as TypeScript judges it.
  Mechanism. isInheritedDictionaryRead returns unknown for a value read through an index signature in
  getPropertyTypeForIndexType (element access and destructuring) and in
  checkPropertyAccessExpressionOrQualifiedName, and for a read of a name the type doesn't declare that the lookup
  finds on Object or Function. A value read keeps its key: getIndexedAccessTypeOrUndefined no longer replaces it
  by string. TypeScript then reports a use of the unknown as if it were an entry.
  Why it suffices. Every value read by name goes through one of those two sites, and an unknown can be used only
  after a narrowing that checks it.
  Witnesses:
    chk-open-record-dynamic-key.ts     a key of type string holding toString
    chk-open-record-destructure.ts     the same through destructuring by a computed key
    chk-open-record-proto-property.ts  __proto__ read as a property, which Object's declaration doesn't name
    rule-open-record.ts                constructor read from a Record<string, number> by a literal key
  Controls:
    safe-keys.ts                       a literal, a number and a template literal type, each reading an entry
    dynamic-own-key.ts                 a key of type string, its unknown narrowed to the entry
    map-lookup.ts                      a Map read by a key of type string, and Object.entries of a record

Obligation 2, a read that may find an inherited member, called: TS18046 (TypeScript's code)
  Statement. The same unknown, called.
  Mechanism. As obligation 1; TypeScript reports a call of an unknown.
  Why it suffices. As obligation 1.
  Witnesses:
    chk-record-own-tostring.ts         a record whose literal had a toString entry, its toString called

Obligation 3, a read by a literal key that may find an inherited member, called: TS2571 (TypeScript's code)
  Statement. The same, read by a literal key and called.
  Mechanism. As obligation 1; TypeScript reports a call of an element access of type unknown.
  Why it suffices. As obligation 1.
  Regressions:
    chk-record-own-tostring-element.ts  the toString entry read by a literal key, which the release refuses to call

Obligation 4, a read the library types where no read is checked: TS2550 (TypeScript's code)
  Statement. No program calls Reflect.get, which reads a key as an element access does but types the result as
  T[P], an indexed access type that no read check sees. An element access reads by any key Reflect.get could.
  Mechanism. Reflect.get is deleted from the library; TypeScript reports a property the library lacks as TS2550
  when a later library declares it.
  Why it suffices. Reflect.get is the library's only function that reads a property by a key it is handed.
  Witnesses:
    lib-reflect-get-inherited.ts       toString read from a Record<string, number> by Reflect.get

Obligation 5, a read by a generic key that isn't a union of literals: TS2571 (TypeScript's code)
  Statement. A value read by a key whose type is generic and whose base constraint isn't a union of literals may
  miss, since the key can be instantiated with string or number, which makes the object a dictionary there: the
  read is the indexed access type with undefined. Where the constraint may be a bare string, the key may also name
  an inherited member, and the read is unknown. A constraint that is a union of literals names keys the object has.
  Mechanism. getIndexedAccessTypeOrUndefined, deferring a value read by a generic index type, adds undefined to the
  indexed access type, or gives unknown when an inherited name is assignable to the key's constraint. TypeScript
  then reports a use of the unknown.
  Why it suffices. A read by a generic key is deferred there and nowhere else, element access and destructuring
  alike. K extends keyof T is constrained by string | number | symbol while T is generic, since T may be a
  dictionary, so such a read is unknown too.
  Witnesses:
    chk-record-generic-key.ts          a Record over K read by a K that the caller makes string
    chk-generic-keyof-mapped.ts        the same through a mapped type over K
    chk-generic-key-other-parameter.ts  the same with K bounded by another type parameter
  Controls:
    generic-key-literals.ts            a generic key bounded by a union of literals
    generic-key-number.ts              a generic key bounded by number, its undefined handled

Obligation 6, a read by a generic key returned as the indexed access type: TS2322 (TypeScript's code)
  Statement. The unknown a read by K extends keyof T gives isn't a T[K].
  Mechanism. As obligation 5; TypeScript reports the unknown where a T[K] is returned.
  Why it suffices. As obligation 5.
  Rejected sound code, because K extends keyof T may be a bare string:
    generic-keyof-get.ts               a key the object has, read and returned through K extends keyof T
