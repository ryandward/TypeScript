classes
kind: soundness

Claim. If the lab accepts a program, it declares no class and reads no this or super. So no field is read before
the constructor sets it, no method runs with this unbound, and no super read finds the prototype without the
field.

Counterexample in plain TypeScript. TypeScript checks a class's members against its type, not against the order
construction runs them in: a field initializer may call a method that reads a field declared below it, a base
class's initializer may call an override that reads a subclass field, and a parameter property is assigned only
after every initializer. It types this by where a method is written, not by how it is called, so a method passed
as a callback, read off its object or called through call runs with this unbound. And it types a class's
prototype, its super and its spreads as an instance. Each witness is such a program, accepted by the release.

The core has no classes, no this and no super. A function that returns a record takes a class's place, and a
function takes what it needs as a parameter. That closes every hole above at once instead of one analysis at a
time, and the rules that only classes needed go with them: definite-assignment's TS2897 is gone, since only a
class declares a field with `!`, and its cases are here.

Obligation 2, this or super: TS2903
  Statement. No expression reads this or super.
  Mechanism. checkThisExpression and checkSuperExpression report TS2903 on every this and super.
  Why it suffices. Every this and super an expression reads is checked by one of the two. Without classes, a
  this could still come from an object literal's method or a function, which TS2903 rejects the same way.
  Witnesses:

Obligation 3, an overload its implementation can't accept: TS2394 (TypeScript's code)
  Statement. A method's or a constructor's overload takes nothing its implementation doesn't.
  Mechanism. With every parameter related one way (see parameters), isImplementationCompatibleWithOverload
  rejects a method or constructor overload that widens a parameter, as it already rejected a function's.
  Why it suffices. Every overload is checked against its implementation there.
  Witnesses:
    chk-overload-ctor-param.ts         a constructor's overload admits a key its body doesn't
    chk-overload-method-param.ts       a method's overload admits a key its body doesn't

Obligation 4, a deleted apply, call or bind: TS2339 (TypeScript's code)
  Statement. A function has no apply, call or bind: each binds a this, and the core has none.
  Mechanism. src/lib/es5.d.ts deletes them from Function, CallableFunction and NewableFunction, so a call
  reports TS2339. Their this parameters, narrower than Function's, also kept the library from compiling once
  every parameter related one way.
  Why it suffices. A method is called through the declaration its type has, and the deletion leaves none.
  Witnesses:
    lib-call-unbound-this.ts           a method called through call with any this

Obligation 5, a read before its declaration: TS2912
  Statement. No read of a binding comes before its declaration (see initialization-order).
  Mechanism. checkIdentifier reports TS2912 on the read of the hoisted function that reaches the class before
  the class is declared.
  Why it suffices. initialization-order's argument: the function can't run before its own declaration.
  Witnesses:
    chk-tdz-class.ts                       the function is called above its declaration
