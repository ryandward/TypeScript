write-into-an-object
kind: soundness

Claim. If the lab accepts a program, no name can store a value into a property or index signature that
another name holds at a narrower type, and no read trusts a narrowing an accessor didn't promise.

Counterexample in plain TypeScript. isPropertySymbolTypeRelated and indexInfoRelatedTo relate a writable
property or index signature in one direction only, so { value: string } passes as { value: string | number }
and the wider name stores a number. propertyRelatedTo ignores readonly outside strictSubtypeRelation. And
assignment narrowing reads a property as the value just assigned to it, even through a setter that stores
something else.

Obligation 1, writable position: TS2890
  Statement. A value may flow into a slot whose type holds a writable property or index signature only if
  that position relates both ways, unless nothing else holds the source: a fresh object or array literal, or
  JSX attributes.
  Mechanism. Under valueAssignableRelation, relatedBack checks every writable property and index signature,
  relating the target's type back to the source's, and reports TS2890. Methods and readonly positions are left
  out. In overload resolution, chooseOverload checks the subtype pass's pick as a value, and uses plain
  assignability while arguments are skipped; past three failed overloads, resolveCall reports the overload
  that type-level assignability accepts, so the L failure is the one shown. src/lib declares iterator results
  readonly.
  Why it suffices. A write through a wider name stores a type the original name doesn't hold, and every value
  flow relates every writable position both ways, which leaves no wider type to write through.
  Witnesses:
    rel-object-property.ts             { value: string } widened, and a number stored
    rel-object-index-signature.ts      a writable index signature widened, and a number stored under a new key
    rel-object-optional-property.ts    an optional property that admits undefined, stored into a string
    rel-object-aliased-literal.ts      an object literal bound to a name first, then widened
    rel-readonly-alias.ts              a readonly property written through a mutable alias
    rel-readonly-through-index-signature.ts  a readonly property overwritten by key
  Controls:
    fresh-object-literal.ts            a fresh object literal given a wider type
    fresh-literal-index-signature.ts   a fresh object literal against a writable index signature
    readonly-property.ts               a readonly property widened
    map-as-readonly-map.ts             a Map viewed as a ReadonlyMap
    iterator-wider-return.ts           an iterator standing in for one with a wider return type
    type-level-object-extends.ts       a type-level question about an object
    context-sensitive-argument.ts      overload resolution with a context-sensitive function in a literal
  Rejected sound code, because the type grants the write, whatever the code does:
    readonly-object-into-writable-type.ts  the receiver only reads, but its field is writable
    narrower-writable-field.ts         a record narrows a field the type it is viewed as declares writable
  Rejected sound code, because the library's declaration grants a write it never makes:
    library-mapped-partial.ts          TypeORM's update takes a mapped copy whose methods became fields
    library-phantom-fields.ts          zod's input and output fields, declared writable to carry types

Obligation 2, accessor not narrowed: TS2339 (TypeScript's code)
  Statement. A read may take the type a check or an assignment established only if the property is storage.
  An accessor's getter needn't return what was checked or assigned.
  Mechanism. getFlowTypeOfAccessExpression gives an accessor its declared type instead of the narrowed one.
  L has no code of its own for this yet: the witness is rejected by TypeScript's TS2339 on the getter's
  declared type, and its marker names a fragment of that message.
  Why it suffices. Narrowing reaches a property read only through getFlowTypeOfAccessExpression.
  Witnesses:
    flow-setter-assign.ts              a setter that stores something other than what it was given
  Controls:
    field-check.ts                     a check on a readonly field narrows it
    field-narrowing.ts                 an assignment to a field narrows it
  Rejected sound code, because nothing in a getter's type says two reads agree:
    getter-returning-stored-state.ts   this getter does return stored state

Boundary. Library declarations that collide with the rule: zod's phantom input and output fields, TypeORM's
mapped partial, connect's IncomingMessage.originalUrl against Express's Request, and the AWS SDK's httpAgent.
