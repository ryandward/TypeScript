type-assertion
kind: soundness

Claim. If the lab accepts a program, every value has the type the checker derived for it.

Counterexample in plain TypeScript. x as T, or <T>x, gives x the type T whenever either type is comparable to
the other, without checking the value: checkAssertion takes the assertion's word.

Obligation 1, type assertion: TS2896
  Statement. A value's type comes from its derivation, never from a claim. as const isn't a claim: it makes a
  literal's type exact and readonly, which the literal shows.
  Mechanism. checkAssertion reports TS2896 for every assertion whose type isn't const.
  Why it suffices. as and <T> are the only expressions that claim a type, and as const is only allowed on a
  literal, whose type it reads.
  Witnesses:
    rule-as.ts                         a value asserted to be a type it isn't
  Controls:
    as-const.ts                        as const on a literal
    satisfies.ts                       satisfies checks a value against a type instead of asserting it
  Rejected sound code, because only a parser could say so:
    json-parse-asserted.ts             the text is a number, and the assertion happens to be true
