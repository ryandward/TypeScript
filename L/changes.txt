Changes to TypeScript 6.0.3

Every change this fork makes to TypeScript 6.0.3, the tag v6.0.3 (commit 050880ce5), as of the commit that last
changed this file. `git diff v6.0.3 -- src` shows the same changes as code. Inside src/ the fork changes six
things: it adds twenty-seven diagnostics, changes the checker and two functions in utilities.ts that decide
which files are checked, adds one internal type flag, declares readonly the new objects and collections the
library hands out, deletes from the ES library every effect and every method that changes an object in place,
and corrects the library's declarations that lie about what the engine does. The parser, binder, emitter,
transformers, language service, command line and compiler options are unchanged, and no test baseline has been
updated. L's rules have no compiler option: they are always on. Each change in code carries a comment that
starts `// L:`, in checker.ts, types.ts and the lib, so `grep -rn '// L:' src` finds them. The entries() changes
in dom.generated.d.ts, webworker.generated.d.ts, es2020.bigint.d.ts and es2025.float16.d.ts carry no comment of
their own.

When a commit changes src/, this file changes with it.


Diagnostics (src/compiler/diagnosticMessages.json)

Twenty-seven new errors, from TS2892 to TS2923, each the code of one rule's mechanism in
L/rules/<rule>/rule.txt. The codes left out belonged to mechanisms the fork has since deleted: TS2890, TS2891
and TS2894 to the write rules, TS2897 to definite-assignment, TS2918 and TS2921 to reads that open-record now
types as unknown and width leaves to TypeScript, and TS2922 to conversions, which was withdrawn.

  TS2892  immutable-bindings
          '{0}' must be initialized where it is declared. In L, every binding is assigned once.
  TS2893  immutable-bindings
          Cannot assign to '{0}' because all bindings are constant in L.
  TS2895  non-null-assertion
          This asserts the value is present without checking it. L has no non-null assertions.
  TS2896  type-assertion
          This asserts '{0}' without checking it. L has no type assertions other than 'as const'.
  TS2898  any
          A value of type 'any' was never checked, so it can't flow into '{0}'. Only 'unknown' accepts it.
  TS2899  type-guard-or-assertion-function
          Nothing checks that the function's body proves '{0}'. L has no hand-written type predicates or
          assertion functions.
  TS2900  any
          This value is 'any', which nothing has checked, so L reads it as 'unknown'.
  TS2901  instanceof-constructor
          Nothing in the type '{0}' promises a prototype for instanceof to read, and an arrow function has none.
          Only a construct signature promises one.
  TS2902  classes
          L has no classes. A function that returns a record takes a class's place.
  TS2903  classes
          L has no '{0}'. A function takes what it needs as a parameter.
  TS2904  writes
          This changes an object in place. L builds a new value instead.
  TS2905  ambient-declarations

          declarations.
  TS2906  namespaces

  TS2907  enums

  TS2908  overloads

          signature.
  TS2909  directives

  TS2910  ambient-declarations

  TS2911  void
          A void result may hold anything, and a parameter typed void takes only undefined.
  TS2912  initialization-order
          '{0}' is declared below this read. L reads a binding only below its declaration, so nothing can run the

          names.
  TS2915  width

          '{4}'.

  TS2917  width

          which may hold more, isn't one.
  TS2919  arity
          Parameter '{0}' is required, but the target can be called without it, so it would receive undefined.
  TS2920  any
          Parameter '{0}' takes '{1}', but the target passes '{2}', whose any promises it anything.
  TS2923  records
          Property '{0}' belongs to the engine's '{1}', not to data a record holds, so it doesn't satisfy '{0}' in
          '{2}'.


The checker (src/compiler/checker.ts), by rule

Functions are named as they are in checker.ts. Commits are the ones that made the change; fb73bc43f later
shortened every L comment to one line without changing code.

any (soundness: TS2898, TS2900; 8ac4d727f, 2adfd653a, 29e19bf5e, f0cb8e20c)
- checkExpression returns uncheckedType for every expression whose type is any, so a value of type any reads as
  unknown, and every operation that needs a structure (a property read, a call, new, an element access,
  iteration, a spread, in, instanceof) rejects it. Writing `any` in a type is allowed: only a value is judged.
- uncheckedType is a new intrinsic type, flagged Unknown and printed as unknown. It is a different object from
  unknownType so that a rejection can say the value came from an any.
- getUnionType returns uncheckedType instead of unknownType for a union that holds it. addTypeToUnion marks such a
  union with the new internal flag TypeFlags.IncludesUnchecked, which types.ts defines as Reserved3.
- getNonNullableType leaves uncheckedType as it is: taking out null and undefined checks nothing else.
- valueAssignableRelation is a new relation, with its own cache: assignability for a value flowing into a slot,
  where an any is rejected. assignableRelation still answers every type-level question: conditional types,
  constraints and inference, where an any is no value. The checker uses valueAssignableRelation where values
  flow: checkTypeAssignableToAndOptionallyElaborate, which checks initializers, assignments, returns,
  properties, for-of, satisfies and yield; chooseOverload's assignability pass; resolveCall's reports of
  argument errors; and the check behind the hint that a call would have succeeded against an overload's
  implementation. isSimpleTypeRelatedTo, hasExcessProperties and the T[K] target in structuredTypeRelatedToWorker
  treat it as they treat assignableRelation, two conditional types' check types relate under assignableRelation,
  and reportRelationError's internal assertion checks against the relation that failed.
- chooseOverload: the pass that skips arguments judges stand-ins for them, so it relates under
  assignableRelation, and the overload the subtype pass picks must also accept its arguments under
  valueAssignableRelation. resolveCall: past three failed overloads, the error reports the overload that
  type-level assignability accepts, the one only the value relation rejected, instead of the last.
- isSimpleTypeRelatedTo: under valueAssignableRelation, a source of type any relates only to unknown or a union of
  undefined, null and {}, and anywhere else reports TS2898. An uncheckedType source that fails to relate reports
  TS2898 as well.
- compareSignaturesRelated compares a target parameter that is any itself (isAnyParameterType) as unknown, in
  every relation, and reports TS2920 when the source's parameter refuses it (861f1fc84). It also relates every
  other parameter as a value flow, under valueAssignableRelation, so an any nested in it is refused too; the
  nested relation is started once (isTypeRelatedAsParameterValue and relatingParameterAsValue), since a fresh
  relation's recursion guards don't see the outer one's (7bebec6c6).
- getBindingElementTypeFromParentType reads a parent of type any as uncheckedType, as checkExpression reads a value
  of type any, so a nested destructuring pattern, whose parent is a property's type and never an expression, takes
  apart an unknown (e0bd3fffd).
- errorOrUnchecked and headedIfUnchecked are new: where the rejected type is uncheckedType, they put TS2900 at
  the head of the error's chain. They are used in getPropertyTypeForIndexType (the property doesn't exist),
  checkNonNullTypeWithReporter (the value is of type unknown), invocationError (the value isn't callable),
  resolveInstanceofExpression (the right side isn't a function) and reportTypeNotIterableError.

writes (soundness: TS2904, and TypeScript's own TS2339 and TS2550; a36084efe)
- checkReferenceExpression, which checks every assignment target (=, a compound assignment, ++, --, a
  destructuring target, a for-in or for-of target), reports TS2904 on a property or element access, and
  checkDeleteExpression reports it on every delete.
- getFlowTypeOfAccessExpression doesn't narrow an accessor (8b384c9e3), since a getter runs on every read and
  can read an iterator it advances. The read keeps its declared type, and TypeScript's own TS2339 rejects what
  follows.
- The relation is TypeScript's again for writes. Before the ban, three rules (mutable-array-or-tuple,
  write-into-an-object, delete) made a writable position relate both ways, from 931689677 to 2c957793d. With
  nothing written, a wider name is only a weaker description of a value, so that machinery is deleted:
  compareSignaturesRelated, unionOrIntersectionRelatedTo, signatureRelatedTo, isPropertySymbolTypeRelated,
  propertyRelatedTo, membersRelatedToIndexInfo, indexInfoRelatedTo, typeRelatedToIndexInfo, getVariances,
  getAliasVariances, getVariancesWorker and relateVariances are v6.0.3's text; argumentList,
  relationGrantsWrites, isUnaliasedLiteral, mayBeDeleted, relatedBack, typeLevelVariances, isWritablePosition,
  SignatureCheckMode.FreshArguments, valueVariances and TS2890, TS2891 and TS2894 are gone. What those rules
  added for values that the any rule still needs is filed under any.

immutable-bindings (soundness: TS2892, TS2893; dbe09f6e5, which called it policy until c6cb79ffc)
- checkGrammarVariableDeclaration: a let or var declared without an initializer is TS2892. A for-in or for-of
  variable, an ambient declaration and a catch variable are left alone.
- checkIdentifier: an assignment to a variable is TS2893.

non-null-assertion (soundness: TS2895; 58e788680)
- checkNonNullAssertion reports every `x!`.

type-assertion (soundness: TS2896; ebc32199d)
- checkAssertion reports every `x as T` and `<T>x` except `as const`.

classes (soundness: TS2902, TS2903; f92faa0b1)
- checkClassLikeDeclaration, which checks every class declaration and expression, reports TS2902.
- checkThisExpression and checkSuperExpression report TS2903 on every this and super.
- checkPropertyDeclaration no longer reports definite-assignment's TS2897 (added in 251cbe601): only a class
  declares a field with `!`, and a variable declared `let x!: T` has no initializer, so TS2892 rejects it.

type-guard-or-assertion-function (soundness: TS2899; af679072f)
- checkTypePredicate reports `x is T` and `asserts x` written on a function, method or arrow function that isn't
  abstract. In a function type, an interface's method or an abstract method the predicate is a requirement,
  which assignment checks, and it stays.

instanceof-constructor (soundness: TS2901; 08fd6afb1)
- resolveInstanceofExpression no longer takes Function's own Symbol.hasInstance as the right side's method, and
  reports TS2901 unless every member of the right side's apparent type has a construct signature.

ambient-declarations, namespaces, enums, overloads and directives (soundness: TS2905 to TS2910; 5ee972c58)
- inDefaultLibrary is new: a node is the library's when the program loaded its file as a default library
  (host.isSourceFileDefaultLibrary), TypeScript's own classification of a program's files. Every other file,
  a declaration file included, is the program's, and the bans judge only the program's.
- checkSourceElementWorker reports TS2905 on the outermost ambient declaration of a value
  (isAmbientValueDeclaration: a variable, function, class, enum or namespace, under declare or at a declaration
  file's top level).
- checkInterfaceDeclaration reports TS2910 when an interface's merged symbol has a declaration in the library.
- checkModuleDeclaration reports TS2906 on a namespace that isn't ambient, checkEnumDeclarationWorker TS2907 on
  an enum that isn't, and checkFunctionDeclaration TS2908 on a function declaration with no body that isn't.
- checkSourceFileWorker reports TS2909 at each @ts-expect-error and @ts-ignore the parser recorded, and at a
  @ts-nocheck.
- In utilities.ts, skipTypeCheckingWorker skips only default library files under skipLibCheck, so a declaration
  file of the program's own is checked, and canIncludeBindAndCheckDiagnostics no longer lets @ts-nocheck skip a
  TypeScript file.

parameters and void (soundness: TS2911, and TypeScript's own TS2322 and TS2339; f0d53de57)
- compareSignaturesRelated relates every parameter contravariantly, whatever declared the target (a function, a
  method, a method signature or a constructor) and whatever strictFunctionTypes says; strictVariance, the
  declaration kind it read and the bivariant comparisons are gone. A callback's signature is related in
  StrictCallback mode at every depth, so BivariantCallback is never passed, and a this type relates one way.
- compareSignaturesRelated takes unknown as the target's type at a parameter position the target doesn't reach,
  and compares unknown[] with what a source's rest parameter takes past the target's last parameter.
- VoidFacts is All: a void result is whatever the function returned, so no test rules it out, and
  narrowTypeByTypeFacts gives a void constituent the type a typeof test implies, as it gives unknown's.
- getSignatureApplicabilityError reports TS2911 when an argument whose type includes void goes to a parameter whose
  type includes void, under valueAssignableRelation.
- With method parameters strict, isImplementationCompatibleWithOverload rejects a method or constructor overload
  that widens a parameter (TypeScript's TS2394), filed under classes.

initialization-order (soundness: TS2912; 51453724a)
- isReadBeforeDeclaration is new: the read of a name whose value declaration is a function declaration, or a
  block-scoped variable or binding element, in the same file and outside the library, that ends before the
  declaration begins. A read inside the declaration itself isn't one, and neither is a read the emitter erases
  (isInErasedPosition): inside a type, or a computed name in an interface or a type alias.
- checkIdentifier reports TS2912 on every such read. TypeScript's own check counts a read inside a function as
  deferred and lets it through; holding every read to the order of the file means a function that reads a const is
  declared after it, and is itself read only after its own declaration.

narrowing (soundness: TS2913 and TypeScript's TS2339, TS2366 and TS18046; 6c1f96b0a)
- holdsNoPrimitive and isPrimitiveValuedType are new. structuredTypeRelatedToWorker, before it takes a primitive's
  apparent type, fails with TS2913 when the target is an object type other than the anonymous empty one and the
  source is a primitive, a type constrained to one, or an intersection with one. unionOrIntersectionRelatedTo
  keeps reporting for such a source against a union with an object member, and typeRelatedToSomeType elaborates
  against that member, so the chain names TS2913.
- getTypeFactsWorker gives an object type with no call or construct signature, and object, a function's facts as
  well as an object's, since a function is a value of every object type whose properties a function has.
- narrowTypeByInKeyword's true branch keeps every member, intersecting one that doesn't declare the key with
  Record<key, unknown>.
- getNarrowedTypeWorker returns the type unchanged in the false branch, for instanceof and for a library predicate
  such as Error.isError: an object literal of the tested type fails the test.
- narrowTypeByConstructor, isMatchingConstructorReference and their two calls are deleted, so x.constructor === C
  narrows nothing.
- narrowTypeByEquality keeps, in the true branch of ==, every member but null and undefined, since == converts;
  isCoercibleUnderDoubleEquals is deleted.
- narrowTypeBySwitchOnTrue narrows by a skipped clause only when the clause is boolean, since skipping a clause
  proves only that its value isn't true.

prototypes (soundness: TS2914 and TypeScript's TS2339 and TS2550; b85ec04e5)
- checkObjectLiteral reports TS2914 on a property assignment named __proto__ by an identifier or string literal,
  which sets the object's prototype and makes no property.
- resolveAnonymousTypeMembers drops the prototype a class's static side gets from the binder, so Iterator, the
  library's one class, has none. The library's own prototype fields are deleted (below).

width (soundness: TS2915, TS2916 and TS2917; 82868af24)
- isExactObjectType is new: a fresh object literal written without a spread, the one type that names every
  property its values have. (82868af24 counted a module's namespace object too, but typeof m types any value.)
- An exact target relates only to an exact source that names nothing it lacks (isExactWithin), or TS2917 is
  reported, so subtype reduction in a conditional or array expression can't keep a fresh type over a wider
  member (2477ac7cf).
- propertiesRelatedTo relates a target's optional property that the source doesn't name to what a value of the
  source may hold there, its index signature's type or unknown, unless the source is exact, and reports TS2915.
  At a name every object inherits (getInheritedNames, shared with open-record) the value is unknown regardless.
- typeRelatedToIndexInfo infers an index signature only for an exact source, and otherwise reports TS2916 beneath
  TypeScript's missing-index error.
- The shortcut relating an empty object type to a mapped type with a ? modifier takes only an exact source.
- getSignatureApplicabilityError's first pass, checkApplicableSignatureForJsxOpeningLikeElement's
  (b17ee7942), and unionOrIntersectionRelatedTo for a union target, keep an
  argument's or source's freshness instead of taking its regular type, and silence the excess-property check with
  excessPropertyChecksSilenced, saved and restored around each use. The regular type would be stricter than the
  fresh one checked after it, which TypeScript's overload resolution assumes never happens.

open-record (soundness: TypeScript's TS2339, TS18046, TS2571 and TS2550; b4491c5d3, and as unknown typing in
e3c46a87e)
- isInheritedDictionaryRead is new, with the names Object.prototype and Function.prototype give every object and
  function (inheritedObjectNames and inheritedFunctionNames, at module level). A value read of a dictionary, a type
  whose index signature applies at an inherited name it doesn't declare, by a key that may be that name, is typed
  unknown, from getPropertyTypeForIndexType (element access and destructuring) and
  checkPropertyAccessExpressionOrQualifiedName (property access). A read by a literal key naming no inherited
  member, a number or a template literal type gets the index signature's type with undefined, as before.
- getIndexedAccessTypeOrUndefined no longer replaces a value read's key by string for a type with only a string
  index signature, so a literal key naming a member Object declares is typed as that member.

call-signature (soundness: TypeScript's TS2349; 3329cd10a)
- isUntypedFunctionCall takes only a callee of type any, so a callee assignable to Function with no signature
  of its own is reported as not callable, in a call, a tagged template or a decorator.

arity (soundness: TS2919; 02d3dfcd3)
- compareSignaturesRelated reports TS2919 at a position the target may leave without an argument and the source
  requires, when undefined doesn't relate to the source's parameter, in every relation. (02d3dfcd3 applied it to
  valueAssignableRelation alone, through a check mode 861f1fc84 deleted.)
- The isTopSignature shortcut that related every function to a top signature is deleted; the StrictTopSignature
  guard for subtype reduction stays.

records (soundness: TS2923 and TypeScript's TS2339; 078128b8e)
- isEnginePropertyOf and isEngineDeclaredProperty are new: a property the library declares on an interface or a
  class, followed back through a mapped or spread property's syntheticOrigin, or a tuple's length.
- propertiesRelatedTo reports TS2923 when an engine property stands in for one a type outside the library declares.
- getSpreadType, getAnonymousPartialType and the rest type skip engine properties, as CopyDataProperties copies
  only own enumerable ones.

Rules with no checker change: effects and library-declarations are built in the library alone (below), and
optional-field is a specification only.


The library (src/lib; 89beff3af, comment in fb73bc43f)

Each iterator result and each tuple a built-in entries() yields is a new object that nothing else holds, so the
fork declares them readonly. While the write rules made a mutable tuple invariant for values, this kept sound
code such as an Iterator<T, undefined> used as an Iterator<T, unknown>, or a Map used as a ReadonlyMap, from
being rejected. With writes banned that reason is gone, and the declarations stay because they are true.

Under the esnext libraries three more types hand out new collections with mutable types: ConcatArray's slice(),
an iterator's toArray(), and a ReadonlySet's union, intersection, difference and symmetricDifference. The value
relation measured ConcatArray, every iterator and generator, and ReadonlySet as invariant because of them, so a
Map couldn't be viewed as a ReadonlyMap with readonly values, nor a ReadonlySet or an iterator widened. They are
declared readonly too (3e0509667), and the cost is code that writes into the new collection,
which L doesn't write.

- es5.d.ts: ConcatArray's slice() returns a readonly array.
- es2015.iterable.d.ts: IteratorYieldResult's and IteratorReturnResult's done and value are readonly. These yield
  readonly tuples: entries() of Array, ReadonlyArray, Set and ReadonlySet; [Symbol.iterator]() and entries() of
  Map and ReadonlyMap; entries() of Int8Array, Uint8Array, Uint8ClampedArray, Int16Array, Uint16Array,
  Int32Array, Uint32Array, Float32Array and Float64Array.
- es2020.bigint.d.ts: entries() of BigInt64Array and BigUint64Array.
- es2025.float16.d.ts: entries() of Float16Array.
- es2025.iterator.d.ts: an iterator's toArray() returns a readonly array.
- es2025.collection.d.ts: ReadonlySet's union, intersection, difference and symmetricDifference return a
  ReadonlySet.
- dom.generated.d.ts: entries() of CSSNumericArray, CSSTransformValue, CSSUnparsedValue, DOMTokenList, NodeList
  and NodeListOf; the iterator and entries() of FormData, Headers, URLSearchParams, MediaKeyStatusMap and
  StylePropertyMapReadOnly; the async iterator and entries() of FileSystemDirectoryHandle.
- webworker.generated.d.ts: the same for the eight of those it declares: CSSNumericArray, CSSTransformValue,
  CSSUnparsedValue, FormData, Headers, StylePropertyMapReadOnly, URLSearchParams and FileSystemDirectoryHandle.


The library's effects (src/lib; 8ab65f25b)

TypeScript-L compiles only the functional core, which performs no effects, so the fork deletes every effect from
its ES library, as L-hooks' pure lib does, and the rule effects holds the deletions. A type stays wherever a value
of it can be handed in from the shell; only the value or the method that performs the effect goes. Each file the
deletions touched opens with a `// L:` comment saying what it no longer declares, and 1,575 lines go in all.

- Runs code from a string: eval and Function's constructor (es5).
- Draws a random number: Math.random (es5).
- Reads the clock: Date's constructor and statics (es5), and Temporal.Now (esnext.temporal).
- Reads the machine's time zone: Date's local-time getters and setters, toDateString and toTimeString (es5).
- Observes the garbage collector: WeakRef and FinalizationRegistry (es2021.weakref).
- Shares memory between threads: Atomics and SharedArrayBuffer (es2017.sharedmemory).
- Reads the machine's locale: every declaration of namespace Intl, in es5, es2020.bigint and the ten intl files
  from es2016.intl to esnext.intl; and all 53 locale methods (toLocaleString, toLocaleDateString,
  toLocaleTimeString, toLocaleUpperCase, toLocaleLowerCase and localeCompare), in es5, es2015.core,
  es2020.bigint, es2020.date, es2020.number, es2020.string, es2025.float16 and esnext.temporal.

The library's declarations made true (src/lib; 6b878d78b)

The core's library declared things the engine doesn't do, and each lie let a crash through. The rule
library-declarations holds each correction to a witness that crashed on it. Code written to the old declarations
stops compiling, which costs nothing L keeps.

- Function has no caller or arguments, which throw on a strict-mode function (es5).
- JSON.stringify returns string | undefined (es5).
- A regex match's elements past the whole match are string | undefined (RegExpMatchArray and RegExpExecArray in
  es5), and so are its named groups (es2018.regexp) and their indices (es2022.regexp).
- Array has no call or construct signatures, which made holes typed as elements (es5). isArray, from and of stay.
- Array.from and Array.fromAsync of an array-like that isn't iterable give (T | undefined)[], and a map function
  over one is handed T | undefined (es2015.core, es2015.iterable, esnext.array).
- reduce and reduceRight have no overload without a starting value, on arrays, typed arrays and iterators (29
  overloads, in es5, es2020.bigint, es2025.float16 and es2025.iterator).
- There is no Proxy, whose reads run its handler (es2015.proxy), and no Object.groupBy, whose result has a null
  prototype (es2024.object).
- matchAll and replaceAll take a string, never a RegExp, which throws without the g flag (es2020.string,
  es2021.string).
- An iterator's flatMap takes a callback that returns no string, which it throws on (es2025.iterator).
- WeakMap and WeakSet keys are objects: WeakKeyTypes has no symbol, since a registered symbol throws as a key
  (es2023.collection).
- ReturnType, Parameters, InstanceType and ConstructorParameters bound a function by (...args: never) => unknown
  (es5), which takes no argument list, so every function satisfies it under arity and the any parameter rule;
  ReturnType and InstanceType give unknown, not any, for a type that isn't one.
- String.raw takes a TemplateStringsArray beside the record it declared (es2015.core): a template's raw is own and
  not enumerable, so under records the engine's object is no record.
- IteratorYieldResult and IteratorReturnResult (es2015.iterable), PromiseFulfilledResult and PromiseRejectedResult
  (es2020.promise), PropertyDescriptor and TypedPropertyDescriptor (es5) are type literals, not interfaces: the
  engine builds each as a plain object with own enumerable data, and records reads an interface as an engine object.
- Reflect.get is deleted (es2015.reflect): it reads a key as an element access does but types the result as an
  indexed access type, which no read check sees (open-record).
- Array.from takes a string as itself (es2015.iterable), returning its code points, since a string is no longer
  an Iterable: no primitive is a value of an object type (narrowing).
- No constructor declares a prototype: all 56 prototype fields are deleted from the core's library, since a
  constructor's prototype is not one of its instances (Map's has no Map state, Date's no time). Object.create and
  Reflect.construct are deleted, since each builds an object on a prototype it is handed (es5, es2015.reflect).
- split with a RegExp separator returns (string | undefined)[], and so does a RegExp's [Symbol.split] (es5,
  es2015.symbol.wellknown): a capture group that took no part splices in undefined. A string separator still gives
  string[]. Array.isArray narrows to readonly unknown[], not any[] (es5). concat takes T or a readonly T[], never
  the structural ConcatArray (es5): it spreads only an array, or an object marked isConcatSpreadable into holes,
  and appends any other object whole. These four came with the crashes from L-hooks' exemption audit (e0bd3fffd).

The library's writes (src/lib; a36084efe)

The core changes no object in place, so the fork deletes every method and function in its ES library that does,
and the rule writes holds the deletions. Each file the deletions touched opens with a `// L:` comment saying so.

- Array: push, pop, shift, unshift, splice, sort and reverse (es5), fill and copyWithin (es2015.core).
- Every typed array (es5, es2020.bigint, es2025.float16): set, fill, sort, reverse and copyWithin.
- DataView's eleven setters (es5, es2020.bigint, es2025.float16), and Date's eight UTC setters (es5); the
  local-time ones went with the effects.
- Map's set, delete and clear, Set's add, delete and clear, WeakMap's set and delete and WeakSet's add and delete
  (es2015.collection), and Map's and WeakMap's getOrInsert and getOrInsertComputed (esnext.collection).
- Object.defineProperty and defineProperties (es5), Object.assign and setPrototypeOf (es2015.core), and Reflect's
  set, defineProperty, deleteProperty, setPrototypeOf and preventExtensions (es2015.reflect).
- ArrayBuffer's resize, transfer and transferToFixedLength (es2024.arraybuffer), SharedArrayBuffer's grow

The library's members the strict relation can't type (src/lib; f0d53de57)

With every parameter related one way, two parts of the library no longer compiled, and the core uses neither:

- Iterator's and AsyncIterator's return and throw take never and return IteratorResult<T, unknown> (es2015.iterable,
  es2018.asynciterable), and Generator and AsyncGenerator inherit them (es2015.generator, es2018.asyncgenerator).
  return took a TReturn in, which made TReturn invariant: with Iterable's any defaults the any rule then refused an
  array as an Iterable, and Generator's required parameter didn't fit IteratorObject's optional one. f0d53de57
  deleted the two members, which let an iterator whose return is a number pass as an Iterator, and for-of calls
  return when a loop breaks; b37cbf035 declares them again, taking never, and the regression case
  lib-iterator-return-number holds it.
- Function's, CallableFunction's and NewableFunction's apply, call and bind (es5). Each binds a this, the core has
  none, and their this parameters, narrower than Function's, kept CallableFunction and NewableFunction from
  extending Function.
