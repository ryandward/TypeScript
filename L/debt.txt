Technical debt

Each item says what is wrong, where it shows, and what it costs. all rules is what every proof assumes. An
item about one rule is filed under the rule's name. lab is the checker and the tooling as a whole, and L-hooks
is the hooks, where they no longer match the lab.

all rules
- Every proof assumes an unpolluted realm: the built-ins the core calls are the ones ECMAScript specifies,
  unmodified, so the library's declarations describe them. The core can't change a built-in, since L has no
  writes and no prototypes, but the shell runs in the same realm as ordinary TypeScript, npm code included, and
  can replace a method, patch an iterator, or add a property to Object.prototype, which also adds a name
  open-record's inherited-name check doesn't know. Any of these makes a declaration false and voids every proof
  that rests on it. Nothing in the lab checks the realm; soundness is relative to a discipline in the shell that
  no tool enforces.

any
- After a TS2900, the rejected operation's result is errorType, which carries any's flag, so
  isSimpleTypeRelatedTo reports TS2898 for it as well: one fault, reported twice. GenomeHub's
  packages/client/src/pages/TracksPage.tsx shows the whole chain: TS2900 at json.contigs, a TS2898 in every
  overload of the useQuery call, and then, because the failed overload leaves TQueryFnData uninferred, TS2339
  and TS7006 wherever the query's data is read. Those follow-on errors carry no L code.
- When the target is a type parameter, TypeScript's TS5082 elaboration replaces the relation's chain, and
  TS2898 drops out of it, so the rejection carries no L code. GenomeHub's packages/client/src/lib/queryFn.ts
  shows it. With the item above, this leaves 37 lab-only rejections in GenomeHub without an L code, 10 in the
  server and 27 in the client.
- A typeof query on an any value reads the value through checkExpression, so `type T = typeof v` is now
  unknown where it was any. The trap's commit said any written in a type is unchanged; a type query isn't
  written any, but no case pins the behaviour either way.
- uncheckedType is a different object from unknownType at the six places that test unknownType by identity:
  getTypeForVariableLikeDeclaration, mapTypesByKeyProperty, getConstituentTypeForKeyType,
  getFlowTypeOfReference, assignParameterType and createPromiseReturnType. None is on a structural path, and
  none has been audited.
- lean/Top.lean has no generic container, so rel-any-nested-promise.ts, a Promise<any> held as a Promise of
  an interface, has no counterexample there. Its functions take one argument, so lib-string-replace-callback.ts
  (a rest parameter) and lib-json-stringify-replacer.ts (a second parameter) are covered only by analogy.
- lean/Top.lean has no unions, so a narrowing's else-branch learns nothing there: x !== null on a T | null
  can't be stated. Its narrowing tests are ones the calculus can state, not TypeScript's steps; that
  narrowTypeByTypeof, narrowTypeByInKeyword and the rest compose to no more than these is unproven.
- The calculus's typeof narrowing retypes a variable inside a branch, which holds only because the calculus
  has no assignment. The Lean proof assumes immutable-bindings, and nothing proves the two rules together.
- new isn't in the calculus, so chk-new-any.ts has no mutant.

effects
- Nothing yet keeps a core project to the ES library. The lab compiles its cases against esnext alone, but
  TypeScript-L still accepts lib: ['dom'], loads @types packages through types and typeRoots, and resolves an
  import of an npm package, so a core project can reach a host API or a package the lab never sees.
- A Date's toString reads the machine's time zone, and the library can't delete it: Object declares toString
  for every type. A Date converted to a string without a call, in a template literal, by String() or by +,
  reads the time zone with no declaration at all.
- A Date the shell hands in can be invalid, and Date's toJSON is declared to return a string, though it returns
  null for an invalid date (L-hooks' lib-date-tojson-invalid). No core program can construct a Date, so the
  catalog has no witness for it. Whether the core takes a Date at all, or only what the shell's adapter parsed
  out of one, is undecided.

writes
- The accessor mechanism has no L code. Its witnesses are proved by TypeScript's TS2339 on the read, which shows
  the read got the declared type, not that getFlowTypeOfAccessExpression gave it.
- Iterators and generators are the state the core can still change: next() advances one, and every getter or
  function that reads one can return something new. RegExp's exec and test write lastIndex on a regex with the g
  or y flag. Neither is a write the checker sees, and no rule closes them.
- The ban is the core's. The shell can still change an object it handed the core between a check and an await,
  as flow-await-interleave's Object.assign did inside the core, since narrowing a property path survives the
  await.

ambient-declarations
- The lab has no case for a declaration file of the program's own, or for @ts-nocheck: the tracker compiles one
  .ts file per case. Both were checked by hand when the bans went in (a .d.ts with declare const under
  skipLibCheck, and a @ts-nocheck file whose own error then surfaced).
- A declaration file that says `/// <reference no-default-lib="true"/>` counts as a default library, so its
  declarations are taken as the library's. That is how the library's own files mark themselves, so nothing
  tells a program's file that does it from one of them.
- A function a script declares under a library global's name merges with the library's declaration as its
  implementation, and isn't judged.

directives
- The compiler option noCheck still skips the checker for the whole program, as a directive would for a file.

parameters
- Array, ReadonlyArray and tuples are covariant because getVariances hard-codes them (arrayVariances), not because
  a measurement found it: includes, indexOf and lastIndexOf take T, and a measurement would call T invariant. The
  covariance holds because those only compare and the core's arrays have no writers, but it is trust in the
  library, not a measurement. A Map's key, a Set's element and an iterator's T are measured, and invariant.
- Inference (inferFromSignature) still records method positions as bivariant. It chooses type arguments; the
  relation then checks them one way.

initialization-order
- The rule sees one file. A cycle of imports runs one module's code before another's has finished, so a binding
  imported from a module that hasn't run yet is read before it exists (L-hooks' other-self-import-tdz).

narrowing
- The false branch of Array.isArray removes nothing now, so `Array.isArray(x) ? x : [x]` leaves the array type in
  the second branch. Testing the other member, `typeof x === 'string' ? [x] : x`, narrows both ways.

width
- An object literal's type is exact only while it is fresh. Reading the checker, freshness is set only by
  checkObjectLiteral and dropped by widening, which every declaration and inference goes through, and the
  exact-target check covers the one route left, a fresh type as a relation's target. That is an audit of where the
  flag is set and cleared, not a proof that no path carries a fresh type to another value.
- A generic mapped type target, Partial<T> with T a type parameter, is judged by TypeScript's own rules for
  generic mapped types, which this rule hasn't audited.
- A relation cached while excess-property checks were silenced can hide an excess-property error later. L's
  soundness doesn't rest on that check, since exactness reads freshness.

open-record
- The inherited names are the spec's, written into the checker, so they hold only in an unpolluted realm (see all
  rules).
- An indexed access type, T[K] in a type, isn't a read and isn't checked, so a library function typed through one
  reads past the check, as Reflect.get did. No other is known, but the library hasn't been searched for one.

call-signature
- A value typed Function can't be called now, even when it holds an ordinary function. Nobody has measured how
  much real code calls one; the core has to declare the signature of a function it is handed.


lab
- TypeScript's own test suite has never been run on the lab. Its baselines would change wherever L does, so
  the run is noisy, but a crash in a path no case reaches would go unnoticed without it.
- compare.mjs judges only the lines changed since the merge base with main. The whole-project check that found
  the trap losing its mark (every lab-only rejection, with or without an L code, against a baseline build of
  the commit before) was a script in the scratchpad, not a tool in the repo.
- The tracker doesn't run the Lean, and rule.txt names its mutants by hand, so a renamed mutant goes
  unnoticed.
- The import from L-hooks' witnesses/exemptions took only the programs that crash. The 28 that ran without a
  crash were set aside by that alone, but a program can hold a value outside its static type and still run, so
  each needs judging by type.
- A witness proves a hole by crashing, and only the catalog's crashes are tracked, so a rule's reach is argued
  in its proof, not counted: no tracker number says that a hole without a crashing witness is closed.

L-hooks
- The hooks reject the any keyword, and the let and var keywords, by name. The lab allows all three: it judges
  the value an any holds and how many times a binding is assigned.
- The optional-field spec allows ?? in a parser's own transform, and the hook still rejects it.
- A library's optional mutable array, such as TypeScript's symbol.declarations, has no spelling the hooks
  accept: the naming step asks for a const, and the readonly rule rejects that const. The hooks' own code
  works around it, as testing/dogfooding/LOG.md records.
- The installed copies are on mixed versions: GenomeHub and TrulyGoodWater at 4ec573b, GenomeHub with its two
  exemptions, and Discord_TS older. All three carry the ?: never patch on top.
